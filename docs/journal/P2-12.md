## Why / design decisions (and alternatives rejected)
- **Joint Gate Review**: A gate task owned jointly by `AB` ensures that both students have cross-reviewed and understood each other's code, so that Operator A can explain the guest booking flow and Operator B can explain the manager availability matrix during the professor's oral examination (Viva).
- **Scratch Database for Backup**: Following `.agent/workflows/db-backup.md`, we strictly rejected dumping the working developer database, as it may accumulate test artifacts or local session data. Rebuilding `hotel_phase2_scratch` from migrations and running `seed_demo` ensures a completely deterministic, reproducible dump suitable for university evaluation.
- **PowerShell binary fallback**: On Windows developer machines where PostgreSQL is installed in `C:\Program Files\PostgreSQL\18\bin` but not in system `PATH`, adding automatic fallback detection prevents manual path reconfiguration errors and allows scripts to run seamlessly in any shell.

## Gotchas / things that surprised us
- On Windows, `pg_dump` and `psql` might not be exposed on default PowerShell PATH despite PostgreSQL 18 service running; adding candidate path detection directly into `backup_db.ps1` and `restore_db.ps1` resolved execution without requiring system-wide environment variable changes.
- PostgreSQL does not allow `DROP DATABASE` inside multi-statement transaction blocks (`-c "DROP ...; DROP ...;"`), so scratch databases must be dropped via individual single-command calls.
