   - **Tables**: Manager availability and booking tables are wrapped in `overflow-x-auto` to prevent horizontal viewport clipping on mobile screens.
   - **Tab Navigation**: Manager tabs wrap with horizontal scrolling (`overflow-x-auto whitespace-nowrap`), preserving readability on smaller devices.

## Why / design decisions (and alternatives rejected)

1. **Route-Level Splitting vs Component-Level Splitting**:
   - We split at the route boundary (`React.lazy` on pages). Splitting individual small components (like buttons or cards) would introduce network waterfall delays and flash of unstyled/unloaded content (FOUC). Route-level splitting provides the highest payload reduction with minimal latency.
2. **Placement of `<Suspense>`**:
   - We placed `<Suspense>` inside `Layout.jsx` around `<Outlet />` (with a root-level fallback as guard). This preserves the persistent `Navbar` and `Footer` during route transitions so the user does not experience a jarring full-screen white flash when navigating between pages.
3. **Dedicated Shared Feedback Components**:
   - Previously, each tab and page had its own copy-pasted Tailwind spinner or alert text. Creating `LoadingSpinner`, `ErrorMessage`, and `EmptyState` centralizes styling, ensures consistent Persian copy, and guarantees strict accessibility compliance across the entire app.

## Viva Drill (Oral Exam Questions & Answers)

### Q1: How does route-level code splitting work in React and Vite, and why does it improve web performance?
**Answer**:
Without code splitting, bundlers like Vite/Rollup package all JavaScript code into a single large bundle (`app.js`). When a user visits the website (even just the landing page), the browser must download, parse, and execute all code—including code for the complex manager panel and detail pages that the user may never visit.
By using `React.lazy(() => import('./pages/...'))`, ECMAScript dynamic `import()` statements tell the bundler to emit separate chunks for each route. When the user navigates to a route, React triggers the download of that chunk asynchronously. While the chunk is loading, `<Suspense fallback={...}>` displays a placeholder.
This dramatically lowers the initial bundle size (in our case from ~401 kB to ~277 kB, a >30% drop), reducing Time to Interactive (TTI), First Contentful Paint (FCP), and mobile bandwidth consumption.

### Q2: Why did we wrap `<Outlet />` in `Layout.jsx` with `<Suspense>` rather than only wrapping the root `<Routes>`?
**Answer**:
If `<Suspense>` is only placed outside `<Layout>`, then whenever a user navigates between routes, the entire layout (including the persistent `Navbar`, `VerificationBanner`, and `Footer`) would unmount and be replaced by the loading spinner. This creates layout shifts, flicker, and a jarring user experience.
By placing `<Suspense>` inside `Layout.jsx` wrapping `<Outlet />`, the header navigation, brand logo, and footer remain rendered in the DOM. Only the main content area transitions through the fallback state while the next page's chunk is fetched.

### Q3: What basic accessibility (A11y) considerations were implemented for the feedback components and modal dialogs?
**Answer**:
1. **ARIA Roles**:
   - `LoadingSpinner`: Uses `role="status"` and `aria-live="polite"` with visually hidden screen-reader text (`<span className="sr-only">`) so screen-reader users are informed that data is loading without interrupting other announcements.
   - `ErrorMessage`: Uses `role="alert"` so assistive technologies immediately announce errors to the user.
   - Modals: Use `role="dialog"` and `aria-modal="true"`, pointing `aria-labelledby` to the modal title element (`id="hotel-modal-title"`).
2. **Keyboard & Focus**:
   - Close buttons (`&times;`) that previously lacked text now have explicit `aria-label="بستن"`.
   - Focus rings (`focus:ring-2 focus:ring-blue-500`) are applied to all interactive elements so keyboard-only users can see active focus.

### Q4: How does Vite know where to fetch dynamic chunks when Django is serving the frontend static files?
**Answer**:
In `frontend/vite.config.js`, we set `base: mode === 'production' ? '/static/' : '/'`. During a production build, Vite injects this base URL into dynamic import chunk lookups. When `React.lazy` requests `dist/assets/ManagerPage.js`, the browser requests `/static/assets/ManagerPage.js`. Django's static files handler (or production reverse proxy / WhiteNoise) resolves this path to the static asset directory, ensuring seamless chunk loading without 404 errors.
