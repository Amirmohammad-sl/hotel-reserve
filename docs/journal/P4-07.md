## What was done (3–6 bullets)

  - `PageLoader.jsx`: layout-level loading state preventing layout jumping during dynamic route transitions.
- **Redesigned 404 Not Found Page**: Polished `NotFoundPage.jsx` with Persian typography, route-friendly navigation links (direct return to home and hotel search), high contrast styling, and responsive layout.
- **Unified Feedback States Across Guest & Manager Views**: Replaced fragmented inline spinners, ad-hoc red boxes, and empty lists across `HotelsPage`, `HotelDetailPage`, `MyBookingsPage`, `HotelListTab`, `RoomTypesTab`, `BookingsTab`, `DiscountsTab`, and `AvailabilityTab` with the new common components.
- **Responsive & A11y Audit Pass**:
  - Added `role="dialog"`, `aria-modal="true"`, and `aria-labelledby` to all modal dialogs (`BookingModal`, `HotelModal`, `RoomTypeModal`, `DiscountModal`, and booking cancel confirmation).
  - Ensured all modal close buttons have descriptive `aria-label="بستن"` attributes and visible focus outlines.
  - Added `max-h-[90vh] overflow-y-auto` to all dialog inner containers for mobile viewports.
  - Added ARIA tab attributes (`role="tablist"`, `role="tab"`, `aria-selected`, `role="tabpanel"`) to `ManagerPage`.

## Lighthouse & Manual Accessibility / Responsive Audit

1. **Accessibility (A11y)**:
   - **Screen Readers**: Feedback states now announce state changes via `role="status"` and `role="alert"` with `aria-live="polite"`.
   - **Modal Dialogs**: All modals (`BookingModal`, `HotelModal`, `RoomTypeModal`, `DiscountModal`) set `role="dialog"`, `aria-modal="true"`, and connect headings via `aria-labelledby`.
   - **Icon Buttons**: Modal close buttons (`&times;` and SVG icons) have explicit `aria-label="بستن"`.
   - **Keyboard Navigation**: Added visible focus rings (`focus:ring-2 focus:ring-blue-500`) to interactive tab headers, retry buttons, and modal dismiss buttons.
2. **Responsive UX**:
   - **Small Viewports (Mobile)**: Modals now feature `max-h-[90vh] overflow-y-auto`, ensuring form inputs remain accessible on mobile keyboards and landscape orientations.
   - **Tables**: Manager availability and booking tables are wrapped in `overflow-x-auto` to prevent horizontal viewport clipping on mobile screens.
   - **Tab Navigation**: Manager tabs wrap with horizontal scrolling (`overflow-x-auto whitespace-nowrap`), preserving readability on smaller devices.

## Why / design decisions (and alternatives rejected)

1. **Route-Level Splitting vs Component-Level Splitting**:
   - We split at the route boundary (`React.lazy` on pages). Splitting individual small components (like buttons or cards) would introduce network waterfall delays and flash of unstyled/unloaded content (FOUC). Route-level splitting provides the highest payload reduction with minimal latency.
2. **Placement of `<Suspense>`**:
   - We placed `<Suspense>` inside `Layout.jsx` around `<Outlet />` (with a root-level fallback as guard). This preserves the persistent `Navbar` and `Footer` during route transitions so the user does not experience a jarring full-screen white flash when navigating between pages.
3. **Dedicated Shared Feedback Components**:
   - Previously, each tab and page had its own copy-pasted Tailwind spinner or alert text. Creating `LoadingSpinner`, `ErrorMessage`, and `EmptyState` centralizes styling, ensures consistent Persian copy, and guarantees strict accessibility compliance across the entire app.

## How it works (follow ONE request/click end to end)
1. The user navigates to the website (`/`). The browser fetches only `index.html` and the lightweight `app.js` bundle (277 kB instead of 401 kB), plus the tiny `HomePage.js` chunk.
2. The user clicks on the "پنل مدیریت" (Manager Panel) link in the navbar:
   - React Router updates the route to `/manager`.
   - `Layout.jsx` remains in place; `<Outlet />` detects that `ManagerPage` is not yet in memory.
   - Suspense instantly displays the fallback `<PageLoader />` inside `<main>`, while the browser fetches `dist/assets/ManagerPage.js` (58 kB).
   - Once the chunk arrives, `ManagerPage` mounts seamlessly without unmounting the navigation bar or footer.
   - If an API error occurs during tab fetch, `ErrorMessage` renders an accessible alert with a retry button instead of a broken layout.

## Gotchas / things that surprised us
- In Vite, dynamic imports with `React.lazy` generate asset requests based on the `base` option in `vite.config.js`. Because `base` was set to `/static/` in production, chunks automatically resolve to `/static/assets/[name].js` matching Django's static URL pattern out of the box without special reverse-proxy rewriting.
- Placing `<Suspense>` solely at the root around `<Routes>` caused the entire layout (including header) to flicker on page navigation; moving it inside `Layout.jsx` around `<Outlet />` completely solved the flicker while maintaining route safety.

1. **س: بارگذاری تنبل در سطح مسیر (Route-level Code Splitting) در React و Vite چگونه کار می‌کند و چرا عملکرد برنامه را بهبود می‌بخشد؟**  
   **ج:** بدون Code Splitting، ابزارهای ساخت (مانند Vite و Rollup) کل کدهای جاوااسکریپت برنامه را در یک فایل بزرگ (`app.js`) بسته‌بندی می‌کنند. در نتیجه کاربر حتی برای دیدن یک صفحه ساده مجبور به دانلود کدهای سنگین پنل مدیریت و صفحات دیگر است. با استفاده از `React.lazy(() => import(...))`، کدهای هر مسیر به فایل‌های جداگانه (چانک) تقسیم می‌شوند و مرورگر تنها زمانی که کاربر روی مسیر کلیک کند آن فایل را دانلود می‌کند. در مدت دانلود، کامپوننت `<Suspense>` یک لودر نشان می‌دهد. این کار حجم باندل اولیه ما را از ۴۰۱ کیلوبایت به ۲۷۷ کیلوبایت (کاهش بیش از ۳۰ درصدی) رساند و سرعت لود اولیه سایت و شاخص First Contentful Paint را به شدت افزایش داد.

2. **س: چرا `<Suspense>` را داخل `Layout.jsx` و دور `<Outlet />` قرار دادیم به جای اینکه فقط دور کل `<Routes>` باشد؟**  
   **ج:** اگر `<Suspense>` فقط دور کل روت‌ها در ریشه برنامه باشد، با هر جابه‌جایی بین صفحات، کل صفحه (از جمله منوی ناوبری بالا و فوتر پایین) Unmount شده و با اسپینر جایگزین می‌شود که حس پرش تصویر و چشمک زدن ناخوشایندی ایجاد می‌کند. قرار دادن `<Suspense>` داخل `Layout.jsx` و منحصراً دور `<Outlet />` باعث می‌شود منوی سایت ثابت و پایدار بماند و تنها بخش محتوای متغیر صفحه حالت انتظار را نمایش دهد.

3. **س: چه نکات پایه‌ای در دسترسی‌پذیری (Accessibility یا A11y) برای وضعیت‌های بارگذاری و مودال‌ها پیاده‌سازی شد؟**  
   **ج:** برای لودینگ‌ها از `role="status"` و `aria-live="polite"` به همراه متن مخفی برای صفحه‌خوان‌ها (`sr-only`) استفاده کردیم تا افراد کم‌بینا بدون ایجاد وقفه صوتی متوجه تغییر وضعیت شوند. برای پیام‌های خطا از `role="alert"` استفاده شد تا بلافاصله به کاربر اعلام شود. برای تمامی پنجره‌های مودال، خصوصیات `role="dialog"`, `aria-modal="true"` و `aria-labelledby` تنظیم شد و به دکمه‌های بستن ضربدر (`&times;`) صفت `aria-label="بستن"` و حلقه فوکوس کیبورد داده شد.

4. **س: چطور کدهای جاوااسکریپت تولیدی Vite هنگام اجرای پروژه روی جنگو به درستی لود می‌شوند و خطای ۴۰۴ در چانک‌های داینامیک رخ نمی‌دهد؟**  
   **ج:** در فایل `vite.config.js` گزینه `base` در حالت پروداکشن برابر `/static/` تنظیم شده است. وقتی وب‌پک یا ویت چانک‌های داینامیک را ایمپورت می‌کند، آدرس درخواست را به صورت `/static/assets/[name].js` می‌سازد که دقیقا منطبق بر نحوه سرو فایل‌های استاتیک جنگو در محیط دانشگاهی/تولید است.
