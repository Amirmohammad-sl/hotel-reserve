- Implemented `spa_host_view` in `backend/apps/core/views.py` decorated with `@ensure_csrf_cookie` and `@require_GET` to seed the CSRF cookie upon initial page load and render the SPA host template.
- Added catch-all client-side routing in `backend/config/urls.py` via `re_path(r"^(?!api/|admin/|static/|media/).*$", spa_host_view)` ensuring frontend deep links reload seamlessly while preserving JSON 404 error responses for unknown `/api/` endpoints.
- Added comprehensive automated test suite `SpaHostViewTests` in `backend/apps/core/tests.py` testing root routing, deep links (`/hotels/3`, `/my-bookings`, `/manager/hotels/create`), CSRF cookie seeding, and API 404 isolation.

## Why / design decisions (and alternatives rejected)
- **Fixed Asset Filenames vs Hash-based Filenames**: In standard Vite builds, filenames include dynamic content hashes (e.g., `app-a8f3d.js`). Without an additional manifest parser plugin in Django, a static Django host template would break on every build. Enforcing `assets/app.js` and `assets/app.css` allows Django's template engine to reference static assets cleanly without third-party dependencies (conforming to D-001 and D-002).
- **Negative Lookahead Regex for Catch-All Routing**: Rather than matching all routes (`.*`), using `^(?!api/|admin/|static/|media/).*$` ensures that non-existent API routes (`/api/unknown/`) fall through to Django's `handler404` (returning standard JSON errors) instead of returning HTML 200 responses to frontend fetch requests.
- **Seeding CSRF Cookie on SPA Host View**: Decorating `spa_host_view` with `@ensure_csrf_cookie` automatically establishes the `csrftoken` cookie when a user visits any page in the application. This ensures mutating requests (login, registration, bookings) have access to the CSRF token without requiring a separate preflight handshake.
- **Leading Slash in `STATIC_URL`**: Setting `STATIC_URL = "/static/"` instead of `"static/"` ensures browser asset resolution is absolute from domain root, guaranteeing that nested client routes (such as `/hotels/3` or `/manager/hotels/create`) resolve scripts to `http://localhost:8000/static/assets/app.js` instead of attempting relative subfolder resolutions like `/hotels/static/...`.

## How it works (follow ONE request/click end to end)
1. **Building the Production Bundle**:
   - Developer runs `npm run build` in `frontend/`.
   - Vite compiles React and Tailwind components into `frontend/dist/assets/app.js` and `frontend/dist/assets/app.css`.
2. **Deep Link Initial Request**:
   - User types `http://localhost:8000/hotels/3` directly into browser URL bar and hits Enter.
   - Django's URL resolver evaluates `urlpatterns`. The path `hotels/3` does not match `api/` or `admin/`, and passes the negative lookahead `(?!api/|admin/|static/|media/)`.
   - `spa_host_view` executes: `@ensure_csrf_cookie` attaches `csrftoken` to response cookies; `render(request, "index.html")` evaluates `{% static 'assets/app.js' %}` to `/static/assets/app.js`.
   - Browser receives HTTP 200 with HTML host template.
3. **Client-Side Hydration & Routing**:
   - Browser fetches `/static/assets/app.css` and `/static/assets/app.js` from Django `staticfiles`.
   - React app boots, `BrowserRouter` reads `window.location.pathname` (`/hotels/3`), and matches `HotelDetailPage`.
   - `HotelDetailPage` dispatches `GET /api/hotels/3/` which is cleanly routed by Django's `path("api/", ...)` to `HotelDetailView`.
   - Hotel data renders seamlessly without 404 error.

## Gotchas / things that surprised us
- In Django, relative `STATIC_URL = "static/"` causes deep links like `/hotels/3` to attempt loading assets from `/hotels/static/...`. Ensuring an absolute `/static/` prefix is mandatory for single-page applications.
- Without a negative lookahead regex on the catch-all pattern, undefined `/api/` endpoints would return the SPA HTML document with a 200 status code, breaking frontend JSON error handling. The lookahead `^(?!api/|admin/|static/|media/).*$` keeps the API boundary completely strict.
