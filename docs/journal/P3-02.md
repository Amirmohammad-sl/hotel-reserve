## Why / design decisions (and alternatives rejected)
- **Same-day turnover without conflicts (D-006)**: An interval overlap check using strict inequalities `check_in < req_out AND check_out > req_in` correctly mirrors hotel operations: a guest departing in the morning on Sep 5 and an arriving guest checking in afternoon on Sep 5 do not overlap (`5 > 5` is `False`).
- **Database-level subquery aggregation vs N+1 loops in Python**: Instead of querying RoomTypes, fetching their bookings in Python, and looping in memory, `RoomTypeQuerySet.with_availability` issues a single SQL query using `models.Subquery` with `Sum("rooms_count")`, `Coalesce(..., 0)`, and `Greatest(F("quantity") - F("reserved"), 0)`. This handles high concurrency and thousands of room types with zero N+1 database queries.
- **Dynamic model lookup (`apps.get_model`)**: `apps/hotels/models.py` needs to query `Booking` for availability, while `Booking` foreign keys to `RoomType`. Calling `apps.get_model("bookings", "Booking")` inside `with_availability` decouples import order and prevents Django circular import exceptions.
- **Normalization of coupon codes**: `.get_valid(hotel, code)` strips whitespace and converts codes to uppercase (`.upper()`), preventing human input errors while verifying temporal and usage limits in one database call.

## How it works (follow ONE request/click end to end)
1. **Room search with availability calculation**:
   - In P3-04 / hotel search, a guest searches for rooms from `2026-09-01` to `2026-09-05` in Isfahan.
   - The view executes `RoomType.objects.filter(hotel__city="Isfahan").with_availability(date(2026, 9, 1), date(2026, 9, 5))`.
   - Django executes a single SQL query with an aggregated subquery:
     ```sql
     SELECT "hotels_roomtype".*,
            COALESCE((
                SELECT SUM(U0."rooms_count") AS "total_rooms"
                FROM "bookings_booking" U0
                WHERE (U0."room_type_id" = "hotels_roomtype"."id"
                  AND U0."status" = 'confirmed'
                  AND U0."check_in" < '2026-09-05'
                  AND U0."check_out" > '2026-09-01')
                GROUP BY U0."room_type_id"
                LIMIT 1
            ), 0) AS "reserved",
            GREATEST("hotels_roomtype"."quantity" - COALESCE(...), 0) AS "available_count"
     FROM "hotels_roomtype";
     ```
   - Each returned `RoomType` object directly contains `.reserved` and `.available_count` attributes without extra queries.

2. **Discount code validation**:
   - The guest applies promo code `NOROOZ1405` on checkout.
   - The view simply calls `DiscountCode.objects.get_valid(hotel=hotel, code="norooz1405")`.
   - `get_valid` checks active status, dates (`valid_from <= today <= valid_to`), and max usage (`max_uses is NULL OR used_count < max_uses`).
   - If valid, returns the `DiscountCode` object; otherwise returns `None`.

).first()

## Gotchas / things that surprised us
- In PostgreSQL and Django ORM, `models.Subquery` must be sliced (`[:1]`) when used inside annotations, even if the subquery returns a single aggregated value.
- If no bookings exist matching the subquery filter, `models.Subquery` returns `NULL`. Wrapping the subquery in `Coalesce(Subquery(...), Value(0))` is necessary so that `F("quantity") - F("reserved")` does not evaluate to `NULL`.

2. **س: منطق محاسبه رزروهای همپوشان (Overlap) و تعویض در همان روز (Same-day Turnover) طبق تصمیم D-006 چگونه کار می‌کند؟**
   **ج:** بازه اقامت مسافر به صورت نیمه‌باز $[check\_in, check\_out)$ در نظر گرفته می‌شود. یعنی مسافر در روز خروج اتاق را تحویل می‌دهد. شرط همپوشانی در ORM به صورت `check_in < req_out AND check_out > req_in` پیاده شده است. اگر مسافری تا ۵ام سپتامبر اقامت داشته باشد و مسافر بعدی از ۵ام سپتامبر بیاید، عبارت $5 > 5$ برابر `False` می‌شود؛ در نتیجه هیچ همپوشانی رخ نمی‌دهد و اتاق بلافاصله برای مسافر بعدی در دسترس است.

3. **س: متد `with_availability` چطور از مشکل N+1 Query جلوگیری می‌کند؟**
   **ج:** به جای اینکه ابتدا انواع اتاق‌ها را بیاوریم و سپس در یک حلقه پایتون برای هر اتاق رزروهایش را با کوئری جداگانه بخوانیم ($1 + N$ کوئری)، با استفاده از `Subquery` و `Coalesce` در سطح دیتابیس کل رزروها با یک کوئری SQL محاسبه و به رکوردهای RoomType اضافه (`annotate`) می‌شوند. دیتابیس با استفاده از Index روی فیلدهای تاریخ و اتاق این کار را در بهینه‌ترین حالت انجام می‌دهد.

4. **س: متد `get_valid` در `DiscountCodeManager` چه مواردی را بررسی می‌کند و چرا کد تخفیف را نرمال‌سازی می‌کند؟**
