# PLAN — پروژه رزرو هتل (درس برنامه‌نویسی وب)

> این سند «نقشه کل پروژه» است. جزئیات هر تسک در `docs/tasks/phase-N.md` و وضعیت لحظه‌ای با `python scripts/board.py`.

## ۱. خلاصه
- **موضوع:** وب‌سایت جستجو و رزرو هتل — دو نقش: مدیر هتل و مهمان (کاربر).
- **استک:** Django 5 + PostgreSQL (بک‌اند، View/URL/Form/Manager/Session/Logging) + React (JS) + Vite + Tailwind (فرانت).
- **تیم:** دو نفر (اپراتور A و B) با Antigravity و مدل Flash. هر دو نفر روی یک ریپوی GitHub کار می‌کنند و روی همه کامیت‌ها مسلط‌اند.
- **تعداد تسک:** ۵۷ تسک در ۵ بخش (فاز ۰ تا ۴)؛ هر تسک یک برنچ، یک PR و یک journal دارد.

## ۲. ریسک مهم: React + «Template» درس
PDF درس فاز ۲ را «view، url، template، form» تعریف کرده است. ما React داریم، پس طراحی را «هیبرید» کردیم (D-001):
- View/URL/Form/Manager/Session/Logging همه Django هستند (View ها JSON برمی‌گردانند، ورودی‌ها با Django Form اعتبارسنجی می‌شوند).
- Django Template برای صفحه میزبان React و همه ایمیل‌ها استفاده می‌شود.
- **اقدام:** تسک P0-06 — ایمیل به استاد/دستیار (متن آماده: `docs/PROFESSOR_EMAIL.md`). اگر نپذیرفت، «Plan B» در DECISIONS D-001 (رندر صفحات اصلی با Django Template و نگه‌داشتن React فقط برای بخش‌های تعاملی) — مدل‌ها/Manager ها/Form ها بدون تغییر می‌مانند.

## ۶. قواعد کسب‌وکار کلیدی
- مدل شب‌محور: `check_out` انحصاری؛ ورود و خروج در یک روز مشکل ایجاد نمی‌کند.
- موجودی = تعداد نوع اتاق − مجموع اتاق‌های رزرو فعالِ همپوشان (D-006).
- کد تخفیف: درصدی، متعلق به یک هتل، تاریخ اعتبار، سقف استفاده.
- رزرو بدون پرداخت، بلافاصله «confirmed»؛ لغو فقط قبل از تاریخ ورود.
